# Changelog — SGC UI Brand Palette

## 19.0.2.0.0 (2026-09-01)

### Breaking change (dependency removal)

Removed 22 of 25 declared dependencies. **Old**: `base, web, mail, calendar,
contacts, crm, hr, account, utm, maintenance, hr_payroll_community, project,
project_todo, purchase, hr_recruitment, sale_management, survey,
hr_holidays, hr_attendance, website, eh_uae_payroll_wps,
spreadsheet_dashboard, sgc_employment_certificate, sgc_hr_memos,
sgc_invoicing_dashboard`. **New**: `base, web, base_setup`.

This is safe because the icon-override mechanism (`models/ir_ui_menu.py`)
was already dependency-tolerant — every lookup uses
`env.ref(xmlid, raise_if_not_found=False)`, so a target module that isn't
installed is silently skipped, and self-heals on the next registry
rebuild once that module IS installed. The only things that actually
*required* the hard dependencies were:

1. `data/sgc_brand_menu_overrides.xml` — static XML `<record id="othermodule.xmlid">`
   overrides, which DO require the target module's xmlid to exist at
   parse time. **Removed.** The Python self-healing hook fully replaces
   this feature with no loss of the icon-override capability.
2. The manifest's own `depends` list — reduced to reflect what the code
   actually needs.

If your deployment relies on `sgc_ui_brand_palette` being installed
*after* every branded app so the old XML data file's one-shot overrides
apply, no action is needed — the Python hook re-applies icons on
every registry rebuild regardless of install order.

### New feature — tenant-configurable colour palette

- `res.company` gains `brand_navbar_bg_color`, `brand_navbar_text_color`,
  `brand_link_color` (all `Char`, hex-validated). Reuses the *existing*
  core `res.company.primary_color` / `secondary_color` fields (already
  present for PDF/document branding) rather than duplicating them.
- New "Brand & Theme" panel under Settings (`views/res_config_settings_views.xml`)
  exposes all five colours with the native `widget="color"` picker, plus
  a "Reset navbar colours" button.
- `res.company._get_sgc_brand_css()` builds a per-company CSS override
  string (Bootstrap 5 `:root` custom properties + a `.o_main_navbar`
  rule), injected into every backend page via a `web.layout` template
  extension (`templates/web_layout.xml`). No SCSS recompilation —
  works correctly with multiple companies on one Odoo instance, each
  with different brand colours.
- Existing companies get the new navbar defaults (`#1B2A4A` /
  `#FFFFFF`) automatically on upgrade — these are plain string
  defaults, which Odoo's ORM backfills onto existing rows at column
  creation. No custom migration script needed.

### Removed

- `data/sgc_brand_menu_overrides.xml` (superseded by the existing
  self-healing Python hook — see above).
- `static/icons.orig-backup-20260726/` — a 5.4 MB unreferenced backup
  copy of `static/icons/` with stale (differing) content. Dead weight;
  git history preserves it if ever needed.

### Verification performed before release

All of the following were checked against the live `odoo:19.0`
Community image (not assumed from memory) before writing this version:

- `res.company.primary_color` / `secondary_color` — confirmed real,
  pre-existing fields (`odoo/addons/web/models/res_company.py`,
  exposed via `base.document.layout`).

  `--bs-secondary-rgb` / `--bs-link-color` — confirmed generated by
  Bootstrap 5 (`$prefix: bs-` in
  `odoo/addons/web/static/lib/bootstrap/scss/_variables.scss`).
- `.o_main_navbar` and `--NavBar-entry-color` — confirmed present in
  `odoo/addons/web/static/src/webclient/navbar/navbar.scss`.
- `widget="color"` on a `Char` field — confirmed used in core
  (`odoo/addons/web/views/base_document_layout_views.xml`).
- `base.res_config_settings_view_form` + `<app>/<block>/<setting>`
  structure — confirmed against `base_setup/views/res_config_settings_views.xml`.
- `web.layout` template + `//head` xpath target — confirmed against
  `odoo/addons/web/views/webclient_templates.xml`.
- `{"type": "ir.actions.client", "tag": "reload"}` — confirmed
  registered in `odoo/addons/web/static/src/webclient/actions/client_actions.js`.

### Known limitation (flagged, not guessed around)

No sidebar/AppsBar-specific CSS selector is targeted — Odoo Enterprise's
left sidebar component was not present in the Community image used for
verification. If deployed on Enterprise, the sidebar keeps its default
look until a human verifies the correct selector against a live
Enterprise instance and extends `_get_sgc_brand_css()` accordingly.
